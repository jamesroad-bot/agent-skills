## 追加：file:// 打开方式导致 403（同日晚）
- 实测结论：Ollama 默认放行**任意 localhost 端口**（65067 / 3000 / 8888 预检均 204 + ACAO 回显），但对 `Origin: null`（即双击 `file://` 打开的页面）预检直接返回 **403 Forbidden**。故 `file://` 是浏览器侧唯一真实拦路点，改 `OLLAMA_ORIGINS` 通常也无效，只能改用 http 打开。
- 代码改动（index.html 由 1224 → 1241 行 / 86,485 字节）：新增 `IS_FILE_PROTO` 侦测；`LLM_TROUBLE` 拆为 `LLM_FILE_STEP` + `LLM_TROUBLE_BASE` 动态拼接，file:// 下把「403 + 改用 python -m http.server」置顶为 ★ 首条；`humanLlmError` network 分支按协议分流措辞；`initLlm` 在 file:// 下给出 err 级警示；`llmSyncUI` 的来源徽标在 file:// 下改为「本地模型（file:// 下会被拦截，将回退内置）」不再误报绿色。
- 验证：vm 双环境（file: / http:）24 项断言全 PASS。注意跨 vm 上下文 `deepStrictEqual` 比较数组会因原型不同而误报，测试里改用 join 字符串比较。
