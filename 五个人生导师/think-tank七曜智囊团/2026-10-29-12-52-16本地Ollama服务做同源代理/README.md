# 知屿 · 个人信息管家 Agent

一个**本地优先**的个人信息管家：把零散的想法、资料、会议结论和待办随手记进来，系统自动分类、生成摘要、提取关键信息与待办，并在记录之间建立关联。它支持关键词检索、基于已有记录的 RAG 问答、阶段总结与下一步行动建议。

- 前端：原生 HTML / CSS / ES Module，无构建步骤
- 后端：Node.js 原生 HTTP 服务，零第三方依赖
- 存储：本机 JSON 文件，原子写入 + 每日备份 + 导入导出
- 模型：Ollama 原生接口 / OpenAI 兼容接口（LM Studio、vLLM 等）
- 无模型时：自动降级到内置的中文规则引擎，记录、检索、待办、总结仍可用

└───────────────────────────┬─────────────────────────────────┘
                            │ REST + SSE
┌───────────────────────────▼─────────────────────────────────┐
│  Node 本地服务（127.0.0.1:8787）                              │

## 1. 快速开始

### 环境要求

- Node.js **20+**（推荐 22）
- 可选：Ollama，或任何 OpenAI 兼容的本地模型服务
- 现代浏览器（Chrome / Edge / Safari / Firefox）

### 启动

```bash
cd 2026-10-29-12-52-16
npm start
```

打开 <http://127.0.0.1:8787>。

项目**没有第三方依赖**，不需要 `npm install`。首次启动会自动写入一组示例记录（7 条笔记、9 个待办），方便直接体验；在左侧「设置 → 本地数据」或记录列表顶部的提示条中可以一键清空示例。

### 接入本地模型（推荐）

以 Ollama 为例：

```bash
ollama serve
ollama pull qwen2.5:7b
ollama pull bge-m3          # 可选：开启向量混合检索时需要
```

然后在应用左下角「本地规则模式 / 本地模型已连接」→「设置」中：

| 配置 | 值 |
|---|---|
| 接入方式 | Ollama |
| 服务地址 | `http://127.0.0.1:11434` |
| 对话模型 | `qwen2.5:7b` |
| 向量模型 | `bge-m3` |
| 向量混合检索 | 按需开启 |

点击「测试连接」，看到可用模型后「保存设置」。保存后左下角状态会变为「本地模型已连接」。

### 使用 LM Studio / 其他 OpenAI 兼容服务

1. 在 LM Studio 中加载模型并启动 Local Server（默认 `1234` 端口）。
2. 设置中选择「OpenAI 兼容」，地址填 `http://127.0.0.1:1234/v1`。
3. 对话模型填 LM Studio 中显示的模型 ID。
4. 本地服务通常不需要 API Key；如使用需要鉴权的网关，可填写 API Key（只保存在本机）。

> 不连接模型也能完整使用：会自动使用本地规则做分类、摘要、要点和待办抽取；问答会返回带出处的检索结果，阶段总结会生成基础版复盘。

### 常用命令

```bash
npm start           # 启动服务
npm run dev         # Node --watch 开发模式
npm run reset-demo  # 重置为示例数据（建议先停止服务）
```

环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | 服务端口 |
| `HOST` | `127.0.0.1` | 监听地址；改成 `0.0.0.0` 会暴露到局域网，见安全说明 |
| `ZHIYU_DATA_DIR` | `./data` | 数据目录 |
| `ZHIYU_API_KEY` | 空 | 模型服务 API Key，优先级低于设置页中保存的 Key |
| `ZHIYU_AI_TIMEOUT` | `120000` | 单次模型请求超时（毫秒） |

Windows PowerShell 设置端口示例：

```powershell
$env:PORT=8899; npm start
```

## 2. 功能一览

### 快速记录
- 一个输入框接收想法、摘录、会议纪要、待办、链接，不需要先选分类。
- 保存后自动完成：标题、类型、标签、一句话摘要、关键信息、关键实体、待办抽取、相关记录。
- 可以关闭「自动整理」只使用本地规则，也可以随时对单条记录「重新整理」。

### 记录流
- 按类型筛选（想法 / 资料 / 会议 / 待办 / 链接）、按主题标签筛选。
- 最新 / 最早 / 标题排序。
- 详情页可编辑标题、标签、原文；修改原文后自动重新整理。
- 相关记录以卡片形式展示，可跳转。

### 关键词检索
- 服务端 BM25 排序，标题、标签、摘要、要点、正文分别加权。
- 支持中文 bigram、英文单词；单字或特殊词有子串兜底。
- 搜索结果显示命中片段并高亮。
- 可以叠加类型与标签过滤。

### 智能问答
- 先检索你的笔记与未完成待办，再让本地模型基于材料回答。
- 回答中的 `[1]` `[2]` 可点击定位到对应引用卡片；引用卡片可打开原文。
- 严格要求模型「只依据材料回答」，材料不足时明确说明。
- 宽泛问题（「我最近在关注什么」）会按时间线取近期记录，避免关键词误命中。
- 没有模型时，用本地检索结果组织一个可读的降级回答。

### 自由聊天
- 直接与本地大模型对话，**不检索、不引用你的笔记**，聊什么都不会被记进记录。
- 支持多轮上下文：会话历史只在本机内存流转，随请求发送给模型，落盘时存入 `chatThreads`。
- 左上角「清空」可结束当前对话并清除本地会话记录。
- 未连接模型时会给出配置引导，而不是报错卡住。

### 待办
- 从记录中自动提取，保留完成状态（重新整理不会把已完成的待办变回未完成）。
- 手动添加，设置截止日期、提醒时间与优先级。
- 按「已逾期 / 今天 / 未来 7 天 / 以后 / 已完成」分组。
- 显示来源笔记，可跳回原文。

### 到点提醒
- 每条待办可以单独设一个提醒时间，点待办行右侧的时钟按钮：5 个快捷选项（30 分钟后、1 小时后、3 小时后、明天 09:00、下周一 09:00）或自定义日期时间。
- 在笔记详情的「关联待办」里也能直接设提醒。
- 到点后右下角弹出提醒卡片，可直接「标记完成」或「10 分钟后」再提醒一次。
- 授权后可同时发系统通知（设置 → 到点提醒 → 开启通知）。
- 前端每 30 秒轮询一次 `/api/reminders`，页面切回前台时立即补查；提醒未确认前不会丢失。
- 已知边界：提醒依赖页面内的定时检查，浏览器完全关闭时不会弹通知。想要「关掉浏览器也提醒」，需要额外的常驻进程或系统级通知中心，本项目未内置。

### 阶段总结
- 时间范围：本周 / 近 30 天 / 全部时间。
- 输出：一句话总结、整体观察、主题洞察、已推进事项、悬而未决事项、3–5 条下一步行动。
- 行动可以直接加入待办；总结可以保存为一条新笔记。
- 历史总结保存在本地，最多保留 30 份。
- 没有模型时生成确定性的基础复盘。

### 关系图谱
- 基于 TF-IDF 相似度 + 标签 Jaccard 自动连边，每条记录最多保留 4 条最强关联。
- Canvas 力导向布局，节点颜色区分类型，悬停查看标题，点击打开原文。
- 关联不是「文件夹」，而是内容之间自然生长的连接。

### 设置与数据
- 模型服务地址、模型名、温度、自动整理开关、向量检索开关。
- 连接测试，展示服务端可用模型。
- 统计、导出备份、导入备份、清除示例、清空全部数据。

### 快捷键
| 快捷键 | 行为 |
|---|---|
| `⌘/Ctrl + K` | 聚焦搜索 |
| `⌘/Ctrl + Enter` | 打开快速记录；记录弹窗内为保存 |
| `Enter`（问答/聊天输入框） | 发送 |
| `Shift + Enter` | 问答/聊天换行 |
| `Esc` | 关闭弹窗 / 抽屉，或从移动端详情返回 |

### 一次记录整理的调用链

```
public/app.js  submitCapture()
  → POST /api/notes
    → pipeline.createNote()
      → nlp.baseNote()                 标题/类型/标签/摘要/要点
      → llm.chat(json)                 AI 结构化整理（可选）
      → mergeAI()                      合并模型结果
      → syncAutoTodos()                创建/更新待办，保留已完成状态
      → nlp.relateAll()                计算 top4 相关记录
      → llm.embed()                    可选：写入向量
      → store.save()                   60ms 去抖 + 原子写盘
  → 前端 refresh() 并选中新记录
```

### 位置

### 可靠性设计

- **原子写入**：先写 `store.json.<pid>.tmp`，再 `rename` 覆盖正式文件，避免中途断电留下半截 JSON。
- **去抖**：60ms 内的连续写操作合并，减少磁盘 IO；退出时 `flush()` 强制落盘。
- **每日备份**：启动时把当天首次见到的数据库复制到 `data/backups/store-YYYY-MM-DD.json`，最多保留 7 份。
- **损坏恢复**：若 JSON 解析失败，会把损坏文件另存为 `store.broken-<timestamp>.json`，并以空数据启动，避免直接覆盖。
- **导出**：`GET /api/export` 下载完整数据（不含 API Key）。
- **导入**：`POST /api/import` 整体替换；导入前前端会二次确认。

### 规模与取舍

JSON + 内存索引适合**个人几千到一两万条记录**。每次检索会在内存中重建 BM25 索引，简单、可移植、零依赖。若记录达到数万条，建议迁移 SQLite：

- `notes` / `todos` 表 + FTS5 全文索引；
- 向量写入 sqlite-vec 或独立向量库；
- 保留同样的 API 契约，前端无需改动。

### 隐私边界

- 服务默认只监听 `127.0.0.1`，局域网其他设备无法访问。
- 除配置的本地模型地址外，应用不发起任何外部请求，无遥测、无云同步。
- 数据以**明文 JSON**保存在磁盘；如需更强保护，请开启系统磁盘加密（BitLocker / FileVault / LUKS），并妥善保管备份文件。
- 若把 `HOST` 改为 `0.0.0.0`，应用没有登录鉴权，等同把私人笔记暴露给局域网，**不建议**在不可信网络中使用。

## 6. 本地大模型接入方式

### 6.1 Ollama（默认）

| 能力 | 接口 |
|---|---|
| 连接检测 | `GET {baseUrl}/api/tags` |
| 对话 | `POST {baseUrl}/api/chat` |
| 向量 | `POST {baseUrl}/api/embed` |

- 非流式整理使用 `stream: false`，并通过 `format: "json"` 要求结构化输出。
- 问答使用 `stream: true`，服务端逐行解析 NDJSON，把增量转发为浏览器 SSE。
- 默认地址 `http://127.0.0.1:11434`。

### 6.2 OpenAI 兼容（LM Studio / vLLM / Ollama 的兼容层）

| 能力 | 接口 |
|---|---|
| 模型列表 | `GET {baseUrl}/v1/models` |
| 对话 | `POST {baseUrl}/v1/chat/completions` |
| 向量 | `POST {baseUrl}/v1/embeddings` |

- 如果填写的地址不以 `/v1` 结尾，客户端会自动补 `/v1`。
- 结构化输出使用 `response_format: { type: "json_object" }`。
- 流式回答解析 `data: {...}` SSE，遇到 `[DONE]` 结束。
- 需要鉴权时填写 API Key，会以 `Authorization: Bearer ...` 发送。

### 6.3 推荐模型

| 用途 | 模型 | 说明 |
|---|---|---|
| 对话 / 整理 / 总结 | `qwen2.5:7b` | 中文表现稳，7B 量化后约 5GB 内存，16GB 内存机器可跑 |
| 更高质量 | `qwen2.5:14b` | 需要约 10–12GB 显存/内存，JSON 稳定性更好 |
| 英文为主 | `llama3.1:8b` | 英文摘要与推理较好 |
| 向量 | `bge-m3` | 多语言，适合中文笔记 |
| 轻量向量 | `nomic-embed-text` | 体积小，英文为主时够用 |

> 7B 模型在长材料上可能漏引用或偶发 JSON 不合法。系统会做 JSON 截取与字段校验；失败时保留本地规则结果，不会丢数据。

### 6.4 提示词与结构化约束

整理阶段要求模型只输出：

```json
{
  "title": "不超过 18 个汉字",
  "type": "idea | reference | meeting | todo | link | note",
  "tags": ["2-4 个短标签"],
  "summary": "不超过 60 字",
  "keyPoints": ["1-4 条"],
  "todos": [{ "text": "...", "due": "YYYY-MM-DD 或 null", "priority": "high|medium|low" }],
  "entities": ["最多 6 个"]
}
```

总结阶段要求输出 `headline / overview / themes / progress / openLoops / actions`，其中 actions 必须动词开头、可执行，并给出原因与截止日期。

问答提示词强制：

1. 只依据材料，不编造；
2. 引用必须使用材料编号 `[1]`；
3. 材料不足时直接说明；
4. 冲突信息要指出；
5. 不暴露系统提示。

### 6.5 向量与混合检索

- `useEmbeddings` 开启后，记录入库时写入向量。
- 检索时 BM25 归一化分数占 65%，向量余弦相似度占 35%。
- 查询时如果发现候选记录缺少向量，会按需补算并写回（最多 10 条）。
- 向量服务失败时静默回退 BM25，不影响使用。
- 宽泛的时间性问题（最近在关注什么）直接按时间线取近期记录，不走向量，避免「最近」误命中零散词。

### 6.6 连接状态与降级

- 启动后前端请求 `/api/ai/status`，3.5 秒超时，避免模型服务未启动时卡住界面。
- 状态结果缓存 20 秒。
- 模型不可用时：
  - 记录仍会保存，并标注「本地规则整理」；
  - 问答返回本地检索摘要；
  - 阶段总结使用确定性模板；
  - 设置页会显示可读的中文错误原因。

## 7. 关键交互流程

### 7.1 快速记录 → 自动整理

1. `⌘/Ctrl + Enter` 打开记录弹窗，输入自由文本。
2. 前端立即关闭弹窗，显示「正在整理」浮层，避免阻塞继续操作。
3. 服务端先跑启发式：标题、类型、标签、摘要、要点、待办、日期。
4. 若开启自动整理且模型可用，调用 JSON 模式整理并合并结果。
5. 同步该记录的自动待办：
   - 文本相同则更新日期/优先级，保留 `done` 状态；
   - 新待办插入；
   - 已被模型删除且未完成的旧待办移除；
   - 手动添加的待办不受影响。
6. 重新计算全库关联，写入 top4 相关记录。
7. 可选写入向量；保存并返回。
8. 前端刷新状态，选中新记录并提示「已整理 / 提取 N 个待办」。

### 7.2 搜索

1. 输入框 230ms 去抖。
2. 请求 `GET /api/search?q=&type=&tag=`。
3. 服务端按类型/标签过滤后做 BM25；标题命中额外加权。
4. 无结果时做子串兜底（覆盖中文单字）。
5. 前端渲染摘要片段，`<mark>` 高亮查询词；点击结果打开详情。

### 7.3 智能问答

1. 用户提问，前端以 `POST /api/ask` 建立 SSE 连接。
2. 服务端先检查模型状态，再检索：
   - 宽泛时间性问题：最近 8 条；
   - 具体问题：BM25 top18，可选叠加向量，取 top6。
3. 上下文包含：最多 16 条未完成待办 + 6 条笔记（标题/日期/类型/标签/摘要/要点/原文 900 字）。
4. 模型流式输出；服务端把增量转为 `delta` 事件。
5. 完成后发送 `citations` 与 `done`，对话存入 `chats`。
6. 前端在回答下方展示引用卡片；`[n]` 点击可闪烁对应卡片，卡片点击打开原文。
7. 模型不可用或流式中断时，自动回退为本地检索回答。

SSE 事件：

```
event: meta   { citations, mode, model }
event: delta  { text }
event: done   { id, citations, mode }
event: error  { message }
```

### 7.4 待办整理

- 自动待办来源：`noteId + auto: true`。
- 手动待办：`auto: false`，不会被重新整理删除。
- 分组在读取时根据 `due` 与今天计算：逾期、今天、未来 7 天、以后、已完成。
- 勾选完成写入 `completedAt`；取消完成清空。
- 提醒时间 `remindAt` 与截止日期 `due` 相互独立：可以只有提醒、只有截止，或两者都有。
- 删除记录时，删除其自动待办；手动待办保留但解除关联。

### 7.5 到点提醒

1. 设时间：`PATCH /api/todos/:id { remindAt }`，服务端统一规整为本地钟点 `YYYY-MM-DDTHH:mm`（无时区，避免跨时区把钟点挪走），非法日期直接视为清除。
2. 改时间会同时把 `remindedAt` 置空，等于重新计时；同一时间重复提交不会重复提醒。
3. 前端每 30 秒请求 `/api/reminders`，服务端返回 `!done && remindAt <= 现在 && !remindedAt` 的待办，按提醒时间升序。
4. 每轮最多弹 3 张卡片，多出来的不确认、留到下一轮，避免一次刷屏。
5. 卡片出现时：右下角渲染提醒卡片（完成 / 10 分钟后 / 知道了）+ 若已授权则发一条系统通知，然后调用 `/ack` 写入 `remindedAt`，保证刷新页面不会重复打扰。
6. 「10 分钟后」= 把 `remindAt` 改成 10 分钟后并清空 `remindedAt`；「标记完成」= `done: true`，之后不再进入提醒队列。
7. 页面从后台切回前台时立即补查一次，避免后台标签页的定时器被浏览器节流后漏提醒。

### 7.6 阶段总结

1. 选择本周 / 近 30 天 / 全部。
2. 服务端筛选该时间段的记录、已完成待办、未完成待办。
3. 将最多 60 条记录压缩为「日期 / 标题 / 类型 / 标签 / 摘要 / 要点」材料。
4. 模型输出结构化 JSON；校验字段、截断长度、规整日期与优先级。
5. 失败则使用模板：主题来自高频标签，进展来自已完成待办，行动来自未完成待办。
6. 保存总结（最多 30 份），前端渲染主题卡片、进展、悬置事项、行动清单。
7. 「加入待办」调用 `/api/todos`；「保存为笔记」把总结转成 Markdown 记录并重新计算关联。

### 7.7 关系图谱

1. 入库/修改时，对每条记录与其他记录计算：
   - 内容 token 的 IDF 加权余弦；
   - 标签 Jaccard；
   - 综合分数 ≥ 0.08 的前 4 条写入 `links`。
2. `/api/graph` 汇总去重后的边。
3. 前端 Canvas 力导向模拟：斥力 + 弹簧 + 向心力，节点半径随度数增大。
4. 悬停高亮邻居并显示标题；点击节点打开记录详情。

## 9. 前端实现说明

### 状态

集中在 `S` 对象：数据、当前视图、选中记录、筛选、搜索、问答消息、总结状态、图谱实例等。所有写操作完成后调用 `refresh()` 重新拉取 `/api/state`，保证前后端一致；问答流式过程直接操作 DOM，完成后统一重绘，避免每个 token 都重排整页。

### 视图

- `notes`：列表 + 详情双栏；移动端通过 `.show-detail` 切换。
- `todos`：统计卡、完成进度、快速添加、分组列表。
- `ask`：引导页 / 消息流 / 引用卡片 / 固定在底部的输入框。
- `summary`：时间范围、总结正文、历史侧栏。
- `graph`：全屏 Canvas + 覆盖层标题与图例。

### 安全

- 所有用户内容在插入 HTML 前转义；Markdown 渲染器先转义再生成受控标签。
- 链接只允许 `http/https`。
- 动态 ID、标签名写入属性时统一转义。
- 后端静态资源做路径穿越校验。

### 响应式

- `>980px`：完整三栏 + 侧栏主题。
- `760–980px`：侧栏收为图标栏，详情与列表仍并列。
- `<760px`：顶部横向导航，列表/详情单栏切换，设置入口移到顶栏。

## 10. 验证与排查

### 冒烟检查

```bash
curl http://127.0.0.1:8787/api/health
curl "http://127.0.0.1:8787/api/search?q=首页"
curl -X POST http://127.0.0.1:8787/api/notes \
  -H "Content-Type: application/json" \
  -d '{"text":"明天要预约牙医，记得带医保卡","useAI":false}'
```

### 常见问题

**左侧一直显示「本地规则模式」**
- 确认 `ollama serve` 已运行。
- 浏览器打开 `http://127.0.0.1:11434/api/tags` 是否能返回 JSON。
- 设置中的地址不要带 `/api`，Ollama 填 `http://127.0.0.1:11434`。
- 点击「测试连接」查看具体错误。

**提示模型不存在**
```bash
ollama list
ollama pull qwen2.5:7b
```
设置中的模型名要与列表一致（可带 `:latest`）。

**整理很慢 / 超时**
- CPU 跑 7B 较慢，首次加载模型需要时间；可换更小模型（如 `qwen2.5:3b`）。
- 关闭「向量混合检索」可减少一次模型调用。
- 设置 `ZHIYU_AI_TIMEOUT` 增大超时。
- 模型失败时记录仍会以本地规则保存，不会丢失。

**总结报「这个时间段还没有记录」**
- 当前范围没有笔记；切换到「全部时间」或先记录一条。

**端口被占用**
```bash
PORT=8899 npm start
```

**数据在哪里 / 如何迁移**
- `data/store.json`；复制整个 `data/` 即完成迁移。
- 也可以「设置 → 导出备份」，在另一台机器导入。

**如何彻底重来**
- 停止服务，删除 `data/`，再 `npm start`（会重新生成示例数据）。
- 或在设置中「清空全部数据」，设置会保留。

## 11. 设计取舍与已知限制

- **为什么用 JSON 而不是数据库**：个人场景数据量有限，零依赖、可直接阅读和备份，降低本地部署门槛。代价是每次检索需内存建索引，规模上限较低。
- **为什么保留规则引擎**：本地模型不一定常开，JSON 输出也可能失败。规则引擎保证「记录永远能存下、能搜到、能形成待办」。
- **为什么问答只取 6 条**：7B 模型在长上下文中容易漏引用；少而准的材料比塞满上下文更可靠。后续可做 chunk 级检索与重排。
- **关联阈值 0.08**：偏低以鼓励连接，但可能产生弱关联；详情页只展示分数最高的 4 条，图谱可直观看到结构。
- **没有做**：多端同步、账号体系、OCR/PDF 导入、浏览器插件、日历双向同步、增量索引、chunk 级 RAG、对话式修改记录。这些都可以在现有 API 上扩展。
- **模型生成内容可能有误**：问答与总结都提供引用或来源，请以原文为准；重要决定不要只依赖模型输出。

## 12. 后续可扩展方向

1. **SQLite + FTS5**：替换 JSON 存储，支持更大数据量与增量索引。
2. **Chunk 级 RAG**：长笔记切块、重排（rerank），提高引用精度。
3. **后台任务队列**：把整理、向量化放到队列，记录保存后立即返回。
4. **多模态输入**：图片 OCR、PDF 解析、网页剪藏。
5. **时间与日历**：把待办同步到系统日历，按精力/时段做排程建议。
6. **加密存储**：使用系统钥匙串保存密钥，对 `store.json` 做透明加密。
7. **多端同步**：端到端加密的同步层，保持本地主副本。
