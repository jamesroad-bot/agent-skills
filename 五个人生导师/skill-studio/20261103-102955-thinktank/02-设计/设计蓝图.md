# 技能设计蓝图：私人智囊团（personal-think-tank）

> 版本：v1.0 · Phase 2 设计产出
> 设计者：蓝致远（skill-architect）
> 唯一事实源：
> - 需求说明书 `01-需求/需求说明书.md`（Phase 1 构思，功能与数据来源口径）
> - 契约规则 `contract.yaml`（v2.0.0，命名与字段规则唯一事实源）
> - 语义判据 `references/description-rubric.md`（QA 判读口径，人工维护）

---

## 0. 设计摘要（TL;DR）

- **形态**：独立技能，纯 LLM 驱动 + 内置静态知识。v1.0 无脚本、无外部 API、无实时数据、离线可用。
- **目录**：仅 2 个 md 文件 —— `SKILL.md` + `references/advisors.md`，无 `scripts/`、无 `hooks/`、无 `commands/`、无 `.lsp.json`。
- **frontmatter**：仅 6 个 marketplace 上架必填字段（name / description / description_zh / description_en / version / author），无 `tools` 字段，也不写 `allowed-tools` / `metadata`（本技能无工具调用、无额外元数据）。
- **输出**：固定五节结构（场景判类 / 五位顾问观点 / 共识与分歧 / 综合结论 / 行动建议）。
- **核心方法论**：「选择 vs 决定」的精确区分是硬判据，必须先判类再展开。

## 1. 目录结构

```
personal-think-tank/                    # 技能根目录，name 与目录名一致
├── SKILL.md                            # 唯一入口：frontmatter + 正文（触发、方法论、输入、输出、边界、示例）
└── references/
    └── advisors.md                     # 内置静态知识：选择/决定四维判据矩阵 + 五位顾问思想风格卡片
```

**各文件职责**

| 文件 | 职责 | 内容来源 |
|------|------|---------|
| `SKILL.md` | 技能唯一入口，承载 frontmatter 与全部行为指令（触发条件、核心方法论行为准则、输入格式、固定五节输出结构、边界、使用示例） | 需求说明书 §四/五/七/八/九/十二 |
| `references/advisors.md` | 内置静态知识唯一权威：完整的「选择 vs 决定」四维判据矩阵 + 五位顾问思想风格卡片 + 顾问观点生成约束 | 需求说明书 §五（矩阵）、§11.2（卡片） |

**明确不存在的结构（合规性）**

- 无 `scripts/`：纯 LLM 驱动，无运行时脚本（详见 §3）。
- 无 `hooks/`、`commands/`、`.lsp.json`：命中 contract `forbidden_paths`，禁用。
- 无 `tests/`、`assets/`、`templates/`：QA 回归用 toolkit 自身 fixtures，不进技能包。
- 无 `README.md`、无 `CHANGELOG.md`：变更说明属发布阶段产物（见 contract `packaging_checklist`），放在发布说明，不进技能目录以保持极简。

**文档预算核算（对齐 contract `doc_budget`）**

| 项 | 上限 | 本设计预估 | 结论 |
|----|------|-----------|------|
| md 文件数 | ≤ 10 | 2 | 通过 |
| md 总行数 | ≤ 1200 | SKILL.md ≈ 180 行 + advisors.md ≈ 80 行 ≈ 260 行 | 通过（余量充足） |
| 标题层级 | ≤ 3 级 | 仅用 `#` / `##` / `###`，无 `####` | 通过 |

## 2. SKILL.md 大纲

### 2.1 frontmatter（字段对照 contract.yaml）

字段必填性事实源：`contract.fields`。workbuddy + marketplace 口径下——

- 核心必填（任意平台/通道）：`name`、`description`
- 上架追加必填（marketplace）：`description_zh`、`description_en`、`version`、`author`
- 禁止：`tools`（出现即 error）
- 可选放行：`allowed-tools`、`metadata`（本技能均不采用，保持最简）

**具体草稿值（实现者可直接采用，语义改动须回设计确认）**

```yaml
---
name: personal-think-tank
description: 当用户面临人生关键分岔口的选择（是否跳槽、创业、买房、换城市、大额投资等）时，由乔布斯、芒格、巴菲特、曾国藩、王阳明五位思想人物组成的「私人智囊团」分别从各自思想风格给出多视角推演，并收敛为可执行的行动建议。触发：用户描述面临选择或犹豫不决的人生场景，或点名本技能或五位顾问之一；不触发：写代码、翻译、事实查询、闲聊、纯情绪宣泄等与人生决策无关的请求。
description_zh: 由乔布斯、芒格、巴菲特、曾国藩、王阳明五位思想人物组成的私人智囊团，在人生关键选择面前提供多视角推演与可执行的决策建议。
description_en: A personal think tank of five thinkers—Steve Jobs, Charlie Munger, Warren Buffett, Zeng Guofan, and Wang Yangming—that provides multi-perspective reasoning and actionable advice for major life choices.
version: 1.0.0
author: 技能全流程创作工坊
---
```

**字段合规核对**

| 字段 | 取值 | 合规依据 |
|------|------|---------|
| `name` | `personal-think-tank` | 匹配 workbuddy 正则 `^[a-z0-9][a-z0-9-]*[a-z0-9]$`，全小写、无下划线、无连续/首尾连字符，长度 19 ∈ [2,64]；与目录名一致（`name_match_dir: warn` 消除） |
| `description` | 一段话，含「做什么 + 触发 + 不触发」双向边界 | 核心必填；对齐 description-rubric 双向边界（项 4） |
| `description_zh` | 简短中文，与 en 语义一致 | marketplace 必填；rubric 项 6 中英一致 |
| `description_en` | 简短英文，与 zh 语义一致 | marketplace 必填 |
| `version` | `1.0.0` | 符合 semver `^\d+\.\d+\.\d+$` |
| `author` | `技能全流程创作工坊` | marketplace 必填（需求已指定该值） |

**description 撰写约束（写给实现者，QA 将逐条核验）**

1. 双向边界：同时写明「触发」与「不触发」，「不触发」条款覆盖最易混淆的相邻场景（写代码 / 翻译 / 事实查询 / 闲聊 / 情绪宣泄）。
2. 触发词具体性：落到用户真实说法（「纠结要不要……」「两个 offer 怎么选」「让芒格帮我看看」），而非抽象功能名词。
3. 能力-实现对齐：只承诺「多视角推演 + 行动建议」，不承诺投资 / 法律 / 医疗结论。
4. 示例不窄化：`description` 中列举的「跳槽、创业、买房、换城市、大额投资」是触发场景的举例，不是全部；正文示例须显式声明「仅为演示，规则本身领域无关」。

### 2.2 正文章节大纲

正文只用 `#`（标题）/ `##`（节）/ `###`（子节），禁用四级标题。

| 章节（`##`） | 内容要点 | 来源 |
|--------------|---------|------|
| `# 私人智囊团`（一级标题 + 一句话定位） | 一句话说明做什么、为谁做 | 需求 §一 |
| `## 触发条件` | 「何时用」（三特征：面临选择/犹豫、分岔口措辞、点名本技能或某顾问）+「何时不用」（三情形：与决策无关通用任务、尚无选择点、纯情绪宣泄/心理干预） | 需求 §四 |
| `## 核心方法论：选择 vs 决定` | 行为准则四条（先判类再展开、选择走全流程、决定轻处理、缺失追问）；点明四维判据名称（可逆性/影响范围/频率/时间尺度）并指向 `references/advisors.md` 获取完整矩阵 | 需求 §五 |
| `## 输入格式` | 自然语言自由文本；期望含 5 项信息（背景/选择点/顾虑约束/时间约束/已尝试努力）；信息不全做「最小必要澄清」，一次 1–3 个关键缺口 | 需求 §七 |
| `## 输出结构` | 固定五节（名称、顺序固定），逐节说明产出要求；判为「决定」时首节后轻处理收尾；内置「最终决定权与责任在用户本人」固定声明 | 需求 §八 |
| `## 边界` | 六条「不做什么」：不提供专业硬承诺、不算命式预测、不替用户做决定、不充当心理咨询、不调用外部实时数据、不做通用任务 | 需求 §九 |
| `## 使用示例` | 一条示例输入 + 示例输出结构示意；示例开头显式声明「仅为演示，规则本身领域无关」 | 需求 §十二 |

**关键设计约定（避免矩阵漂移）**

- 「选择 vs 决定」**完整四维判据矩阵的唯一权威在 `references/advisors.md`**；SKILL.md 正文只写「行为准则 + 四维名称」，不复制表格。两处不重复，防止后续改矩阵时漏改一处导致漂移。
- 「输出五节」的固定节名与免责声明文案写死在 SKILL.md `## 输出结构` 与 `## 边界`，作为内置静态文案（LLM 逐字复述），不放入 references（结构稳定性是行为契约，须与入口同处）。

## 3. 脚本清单

**结论：v1.0 无脚本（`scripts/` 目录不存在）。**

| 候选脚本 | 是否引入 | 裁决理由 |
|---------|:---:|---------|
| 触发判断脚本 | 否 | 意图理解属语义任务，正则/关键词匹配实现触发判断 = rubric A 部分「语义任务降级」一票否决（见 §5 逐条裁决） |
| 选择/决定判类脚本 | 否 | 分类 + 推理，语义任务，非机械枚举 |
| 输出五节结构校验脚本 | 否（延后） | 节名/免责声明是确定性可枚举的，本可脚本化；但本技能输出是 LLM 直接对话，无文件可拦截；且需求明确「如需结构自检可加最小脚本，但 v1.0 不做」。改为把节名/文案写死为静态 prompt |
| 顾问名/思想标签匹配脚本 | 否 | 是固定静态内容，直接写入 prompt/正文即可，脚本化纯属多余 |

**降级路径（无脚本故无运行时依赖）**：本技能不依赖任何第三方库、不依赖解释器、不依赖网络。运行所需全部内容为 SKILL.md 正文 + references/advisors.md 静态文本，由平台运行时随技能装载，离线可用（对齐 AC-9）。

## 4. references 规划

### 4.1 文件：`references/advisors.md`

单一文件，承载两份内置静态知识，作为**完整矩阵与卡片内容的唯一权威**。

**内容结构（标题 ≤ 3 级）**

```
# 内置知识：五位顾问与选择/决定判据

## 一、选择 vs 决定 四维判据矩阵
（表格：判断维度 | 选择（Choice） | 决定（Decision），6 行）
  1. 可逆性 / 2. 影响范围 / 3. 发生频率 / 4. 时间尺度 / 5. 可修正性 / 6. 典型示例

## 二、五位顾问思想风格卡片
（表格：顾问 | 思想标签 | 核心视角（供 LLM 生成观点时对齐））
  乔布斯 / 芒格 / 巴菲特 / 曾国藩 / 王阳明，各一行

## 三、顾问观点生成约束
  - 每位顾问一段，以「顾问名 + 思想标签」开头
  - 观点必须可辨识地体现其思想风格（QA 对照卡片核验，AC-5）
  - 观点之间允许且应当出现冲突
  - 卡片描述的是「通用思想风格」，不限定于某个具体领域（防窄化）
```

**矩阵内容（源自需求 §五，写入时逐字对齐）**

| 判断维度 | 选择（Choice） | 决定（Decision） |
|------|------|------|
| 可逆性 | 不可逆，或逆转成本极高 | 可逆，或低成本即可修正 |
| 影响范围 | 深远、全局、结构性 | 局部、短期、执行性 |
| 发生频率 | 低频（人生屈指可数） | 高频（日常反复发生） |
| 时间尺度 | 影响数年乃至数十年 | 影响数天至数周 |
| 可修正性 | 难以修正、路径依赖强 | 易于修正、试错成本低 |
| 典型示例 | 换行业、是否创业、是否成家、换城市、大额资产配置方向 | 今天先做哪件事、开哪场会、回复哪封邮件 |

**五位顾问卡片（源自需求 §11.2，写入时逐字对齐）**

| 顾问 | 思想标签 | 核心视角 |
|------|------|------|
| 乔布斯 | 聚焦与极致（focus & simplicity，stay hungry, stay foolish） | 追问「这件事是不是你真正热爱的」「如果只剩三个选项你会砍掉哪个」；把资源集中到极少数真正重要的东西上，敢于舍弃 |
| 芒格 | 多元思维模型与逆向思考（invert, always invert） | 先问「怎样会失败/怎样会搞砸」再倒推规避；用多学科视角交叉检验，警惕单一框架与认知偏误 |
| 巴菲特 | 能力圈与长期价值（circle of competence，long-term compounding） | 追问「是否在能力圈内」「十年后回头看还重要吗」；长期复利、拒绝不懂的诱惑、留安全边际 |
| 曾国藩 | 自我修炼与稳健（拙诚、日课、稳扎稳打） | 「结硬寨、打呆仗」，不取巧不冒进；用日课与自我约束对抗浮躁，先求不败再求胜 |
| 王阳明 | 知行合一与致良知（knowing-doing unity，conscience） | 追问「内心良知真正认可的方向是什么」；知而不行只是未知，把判断落到行动上，以内心是非为准绳 |

> 卡片中的英文标签（focus & simplicity 等）为思想风格名，属正常描述文本，不触发敏感/硬编码扫描；无 `example.com` / `localhost` / 假数据 token（张三/李四/Foo/Bar）等 `W-HARDCODED-FAKEDATA` 信号。

## 5. LLM / 脚本分工矩阵

### 5.1 分工总表

| 环节 | 责任方 | 载体 |
|------|--------|------|
| 触发判断（是否唤起） | LLM（意图理解） | SKILL.md `## 触发条件` |
| 选择 / 决定判类 | LLM（分类+推理）+ 静态判据矩阵 | references/advisors.md §一 |
| 澄清追问 | LLM（对话生成） | SKILL.md `## 输入格式` |
| 五位顾问观点生成 | LLM（生成）+ 静态思想风格卡片 | references/advisors.md §二/三 |
| 共识 / 分歧收敛 | LLM（综合生成） | SKILL.md `## 输出结构` 第 3 节 |
| 综合结论与行动建议 | LLM（生成） | SKILL.md `## 输出结构` 第 4/5 节 |
| 输出结构模板 / 固定节名 / 免责声明 | 静态资源（内置文案） | SKILL.md 正文固定文案 |
| 输入信息完整性校验（是否需追问） | LLM（语义判断） | SKILL.md `## 输入格式` |

### 5.2 脚本化边界判定问句逐条裁决

对每一个「是否应该脚本化」的环节，用三问句 + 四个补充问句逐条裁决。裁决规则：只要「理解问句 = 是」（需要理解意图/语义/自然表达）就走 LLM；只有「确定性问句 = 是 + 理解问句 = 否 + 失败问句 = 是」才考虑脚本。

**① 触发判断（是否唤起本技能）**

| 问句 | 裁决 |
|------|------|
| 确定性问句：同输入同输出、可逐条枚举？ | **否** —— 触发表述是自由文本，无法枚举全部「该触发/不该触发」问法 |
| 理解问句：需理解意图/语义分类/自然表达匹配？ | **是** —— 需判断用户是否「面临选择」、是否「点名顾问」 |
| 失败问句：失败模式可预测、可显式报错？ | **否** —— 误唤起/漏唤起不可枚举 |
| 补充：需确定性计算？跨会话状态？外部系统？随上下文变化？ | 均否；但「随上下文变化」是语义级变化，非机械规则可覆盖 |
| **结论** | **LLM（意图理解），不脚本化**。用关键词/正则做触发 = 语义任务被脚本化，rubric A1 一票否决 |

**② 选择 / 决定判类**

| 问句 | 裁决 |
|------|------|
| 确定性问句 | **否** —— 判类依赖用户上下文语义，非机械枚举 |
| 理解问句 | **是** —— 需推理可逆性/影响范围/频率/时间尺度 |
| 失败问句 | **否** —— 判错模式（把「决定」当「选择」）不可预测枚举 |
| **结论** | **LLM（分类+推理）+ 静态判据矩阵（advisors.md）**，不脚本化。矩阵是「规则提示」，不是可执行代码 |

**③ 澄清追问**

| 问句 | 裁决 |
|------|------|
| 确定性问句 | **否** |
| 理解问句 | **是** —— 需判断「缺什么信息」并生成针对性追问 |
| **结论** | **纯 LLM**，不脚本化 |

**④ 五位顾问观点生成**

| 问句 | 裁决 |
|------|------|
| 确定性问句 | **否** —— 观点是生成内容，不可枚举 |
| 理解问句 | **是** —— 需对齐思想风格并生成差异化观点 |
| **结论** | **LLM 生成 + 静态思想风格卡片（advisors.md）**，不脚本化 |

**⑤ 共识 / 分歧收敛 & ⑥ 综合结论与行动建议**

| 问句 | 裁决 |
|------|------|
| 确定性问句 | **否** |
| 理解问句 | **是** —— 综合、收敛、归纳 |
| **结论** | **纯 LLM**，不脚本化 |

**⑦ 输出结构模板 / 固定节名 / 免责声明（唯一「看似可脚本化」的环节）**

| 问句 | 裁决 |
|------|------|
| 确定性问句：固定五节节名、免责声明文案是否确定可枚举？ | **是** —— 节名/文案完全确定 |
| 理解问句：是否需语义理解？ | **否** —— 逐字复述即可 |
| 失败问句：缺节/错序能否显式检测？ | **是**（理论可检测） |
| 补充：需确定性计算？ | **否** —— 只需把固定文案写进 prompt 让 LLM 逐字输出，无需计算 |
| 补充：是否需跨会话状态？ | **否** |
| **结论** | **静态资源（内置固定文案），不脚本化**。理由：目标是「文案不丢失、结构稳定」，把节名/免责声明写死在 SKILL.md 正文即可达成，脚本化反而引入运行时依赖（违背纯 LLM 零依赖定位）。结构自检脚本列为 v1.1+ 的可选增强（需求已声明 v1.0 不做） |

**⑧ 输入信息完整性校验（是否需追问）**

| 问句 | 裁决 |
|------|------|
| 确定性问句 | **否** —— 「缺哪一项信息」随上下文变化 |
| 理解问句 | **是** —— 需语义判断缺口 |
| **结论** | **纯 LLM**，不脚本化 |

### 5.3 裁决结论汇总

- **零脚本**：八个环节全部由「LLM」或「静态资源」承载，无任一环节同时满足「确定性=是 + 理解=否 + 失败=是」的脚本化门槛。
- **灰区（⑦ 输出结构）已按规则拆分**：确定性部分（节名、免责声明文案）下沉为**静态 prompt/文案**，语义部分（每节实际内容）交给 LLM，不引入脚本。
- 本结论与需求 §11.3 的分工表一致，并满足 AC-9（无网络依赖、无 API key、离线可用）。

## 6. 提示设计约束（不窄化原则）

1. **few-shot 示例必须跟随通用原则声明**：`## 使用示例` 中的「离职创业」示例开头必须显式声明「**以下示例仅为演示，规则本身领域无关**」；示例需能还原出通用原则（四维判据 + 五顾问框架），遮住示例、仅凭原则仍应覆盖买房/换城市/关系/读研等任意人生选择场景。
2. **顾问卡片不写成专属特例**：卡片描述的是「思想风格」（通用），不绑定「只对创业/投资场景有效」；观点生成指令须表述为「把该思想风格应用到用户当前场景」，而非「套用某示例的结论」。
3. **示例不窄化是 rubric A3 一票否决项**：发现「原则被示例取代」（通用规则收窄为专属特例）即整体不通过，实现者须自查。

## 7. 风险与权衡

| 风险 / 权衡 | 应对 |
|------------|------|
| description 过度承诺（唤起后做砸） | 双向边界 + 能力-实现对齐：只承诺「多视角推演+行动建议」，专业领域（投资/法律/医疗）仅提供思维框架并附免责声明 |
| 矩阵漂移（SKILL.md 与 references 重复） | 矩阵唯一权威在 advisors.md，SKILL.md 只写行为准则+四维名称，不复制表格 |
| 纯 LLM 无脚本 → 结构稳定性依赖 prompt 而非运行时校验 | 权衡：换取零依赖、零运行时风险，符合需求 v1.0 定位；节名/免责声明写死为静态文案对冲漂移；结构自检脚本留作 v1.1+ 可选增强 |
| 顾问观点「套路化/空洞」 | 卡片写「思想标签 + 核心视角 + 对齐追问模板」，并要求观点可辨识、允许冲突（QA 对照卡片核验，AC-5） |
| 真人名思想人物（乔布斯/芒格等） | 属历史/公众人物思想风格引用，非肖像权或敏感信息；卡片仅描述思想方法论，不做人格化不当表述 |
| 文档极简（2 md） | budget 充裕（≤10/≤1200/≤3 级），2 文件已承载全部行为与知识，无需额外拆分 |
