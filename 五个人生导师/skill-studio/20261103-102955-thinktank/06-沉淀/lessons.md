# 经验沉淀：私人智囊团（personal-think-tank）技能创作

> run-id：20261103-102955-thinktank
> 范围：包外沉淀区，升级不丢失。仅供后续技能创作参考，不进入技能包。

## 本次踩过的坑

1. **成员异步调度慢 / 卡顿**：五个阶段成员（ideator / architect / developer / qa / packager）在本次环境中普遍「长时间运行不落盘」，但最终均能落盘成功。应对：主理人耐心等待 + 适当发消息提示，不轻易中断切换方案；不要反复轮询（会触发系统重复动作拦截）。
2. **QA 报告与打包器产物落盘时序不一致**：QA 会先跑打包器产出 zip，再慢慢写报告；打包师也会先出 zip、再出交付说明。判断「阶段是否完成」应看关键产物（zip / 报告 md）落盘 + 成员发消息，而不是只看目录非空。
3. **「四维判据」称谓漂移**：需求与 SKILL.md 正文用「四维判据」，但 advisors.md 矩阵写了 5 个判据维度（多了「可修正性」）。根因是「可逆性」与「可修正性」语义重叠。裁决：统一为「四维」，把「可修正性」并入「可逆性」，保住需求核心术语不动。→ 教训：核心术语在 SKILL.md 与 references 之间要单一权威，避免两处各自展开导致口径漂移。

## 本次形成的新裁决

1. **免责声明与「最终决定权」声明对等化**：涉及投资 / 医疗 / 法律的专业免责声明，应当与「最终决定权在用户」一样写为「每次输出必含」的固定声明（而非仅作边界行为条款），防止 LLM 长对话中遗漏边界守护。已落实到 SKILL.md「输出结构」固定声明段。
2. **纯 LLM 技能的结构稳定性对冲**：无脚本技能的五节结构 / 固定声明，通过「把节名与声明写死为 SKILL.md 静态文案」来对冲 prompt 漂移；结构自检脚本留作 v1.1+ 可选增强（本次 v1.0 不做）。
3. **「选择 vs 决定」四维判据**（可逆性 / 影响范围 / 发生频率 / 时间尺度）作为本技能方法论内核，资源聚焦在真正的「选择」上，「决定」轻处理——这套判据可复用于其他「决策咨询类」技能。
