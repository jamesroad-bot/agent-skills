# 边界处理

本文件定义四种边界情形的处理流程与默认中文话术。所有处理都必须继续遵守硬约束：中立、不评判、不泄露预设结论、一次一问、不引入未提及的框架或服务。

## 情形 1：用户拒答（user refuses）

判定信号：用户回答"不知道""没想法""你直接告诉我吧""不想答这个问题"，或长时间只给极短回避式回应。

流程：
1. 第 1 次拒答：**不施压、不评判**，把当前问题降级为更易回答的版本，或换一个更具体的切入角度。
   - 话术："没关系，我们换个更小的切口：<把一个开放式大问题拆成一个用户必然能答的具体小问题>"
2. 第 2 次拒答（`user_refusals` 累计到 2）：主动降低强度，给出"继续被追问 / 改为直答 / 就此收尾总结"三个中性选项，由用户选。
   - 话术："要不要我把方式调一下：我可以继续用问题引导你、先给你一个简短的方向、或者基于目前你说的内容做个小结。你更想要哪种？"
3. 第 3 次及以上：默认尊重用户，倾向于收尾——若用户未明确要直答，则先产出"截至目前的反思总结"，并询问是否继续。

红线：不得因拒答而表现出催促、失望或说教；不得替用户"脑补"答案后继续推进。

## 情形 2：用户跑题（off-topic）

判定信号：回答与本 `topic` 明显无关。

流程：
1. **先中立承接**，不回否、不纠正。
2. 若跑题内容与主题**有可建立的关联**：用一个桥接问题把它牵回主题，而不是直接丢弃。
   - 话术："你提到"<跑题内容>"。它和你最初说的"<topic>"之间，你觉得有联系吗？还是我们先回到"<topic>"？"
3. 若跑题**完全无关**：一句话温和归位，重新提出上一个未追完的线索（来自 `open_threads`）。
   - 话术："这个我们放一放；回到刚才那条线：……"

红线：不得连续多轮跟着用户跑题而不归位；不得评判"你跑题了"。

## 情形 3：用户要求直接答案（asks for direct answer）

判定信号："别绕了，直接告诉我结论/答案/该怎么办。"

流程（尊重优先，三步）：
1. 先**满足核心诉求**：给一个**简短、克制**的方向或结论（要点式，不铺陈成长篇）。
2. 随后**一次**询问是否愿意继续被引导：
   - 话术："先给你一句方向：<简短结论>。如果你愿意，我们可以再回到用问题帮你把这一点想透——你继续问，还是就到这里？"
3. 若用户坚持只要答案：停止追问，转入**反思总结**或直接结束，并保留"随时可重新开始引导"的邀请。

红线：
- 给出的"简短结论"不得伪装成本技能推导出的预设标准答案；它是回应用户直答诉求的务实答复。
- 不得在用户已明确要直答时还反复用追问拖延。
- 收尾时仍不得把未经用户认同的结论塞进"用户自己的结论"字段。

## 情形 4：信息不足（insufficient information）

判定信号：主题缺失/过宽、或某轮回答信息量不足以支撑下一个有意义的追问。

流程：
1. 缺 `topic`：不开始追问，先用一句澄清补齐主题。
   - 话术："先对齐一下主题：你希望我围绕哪件事来追问你？可以用一句话描述。"
2. 主题过宽：用**澄清概念**策略把范围收窄到一个可深挖的具体面，再进入正常流程。
3. 单轮信息不足：回到策略 1（澄清概念）补一轮，取得可锚定的具体内容后再生成下一个问题；**绝不**基于臆测硬造后续问题或硬造总结。
4. 若多轮后仍无实质输入（信息始终不足）：诚实收尾，说明"目前信息还不足以继续深入"，并给出反思总结的空缺版（已澄清关键点可为"尚未展开"）。

红线：信息不足时禁止编造主题、编造用户观点、或在总结里填入用户没说过的内容。

## 升级 / 降级一览

| 触发 | 降级动作 | 升级动作 |
|------|----------|----------|
| 拒答 | 问题拆小、换角度 | 累计 2 次→给"继续/直答/收尾"三选项；3 次→倾向收尾 |
| 跑题 | 桥接回主题 | 完全无关→一句话归位并重启上一条线索 |
| 要直答 | 先给简短方向 | 坚持→停止追问转总结 |
| 信息不足 | 澄清补主题/收窄范围 | 始终不足→诚实收尾，产出空缺版总结 |
